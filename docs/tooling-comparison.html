Фильтр

Короткий вывод

У сильных coding-агентов почти всегда один и тот же фундамент: команды, файлы, поиск, правки и защита.

База у всех похожая

Почти везде есть “запусти команду”, “прочитай файл”, “измени файл”, “найди по проекту”. Отличаются не названия, а удобство, безопасность и качество правок.

Большой каталог не всегда лучше

У CodeWhale и Hermes очень много действий. Это мощно, но обычному пользователю сложнее понять, что происходит и почему агент выбрал именно это.

Mothership сейчас намеренно компактный

У нас меньше тулов, зато проще объяснить поведение, легче проверять безопасность и проще строить правильный UI для истории действий.

Голос — это ввод, не действие агента

Диктовка промпта должна превращаться в текст до отправки агенту. Модель не должна видеть audio_transcribe как действие.

Что есть у нас в Mothership

Сейчас модель видит компактный набор. Это хорошо для контроля, но расширять его нужно аккуратно, через понятные пользовательские сценарии.

run_command

Запускает локальные команды под присмотром Mothership: тесты, сборку, git, диагностику проекта.

оставить ядром

read_file, write_file, edit_file

Отдельные понятные действия для файлов: прочитать, создать или точечно поменять.

понятно для UI

apply_patch

Нужен для сложных изменений сразу в нескольких файлах. Пользователю лучше показывать это как “пакет правок”.

важно для серьезных задач

search_text

Ищет текст по проекту. Для обычного пользователя это “найти места в коде”, а не отдельный технический режим.

оставить

image_generate

Появляется только если есть провайдер генерации изображений. Это не обязательная coding-база.

дополнительная возможность

Чего нет в базовом списке

list_files не выдается модели как новый инструмент, audio_transcribe тоже не выдается. Это совпадает с нужной логикой.

логика верная

Спорные вещи и решение

Здесь проверка логики по тем местам, которые легко перепутать в продукте.

audio_transcribe

Это не то, что агент “делает”. Это способ для человека надиктовать сообщение. Правильное место — поле ввода, микрофон, обработка до отправки промпта.

не делать тулой

auto_safe

Это режим защиты: обычное можно пропускать, очень опасное тормозить или спрашивать. В интерфейсе это настройка поведения, а не кнопка и не тул.

режим, не инструмент

list_files

В других проектах чаще встречается не ровно list_files, а Glob, glob, list_dir, чтение папки или команда оболочки. Отдельная тула не обязательна.

можно не показывать модели

Что стоит забрать в Mothership

Не копировать каталоги целиком, а брать понятные продуктовые идеи.

Из OpenCode

Более умные точечные правки и хорошая подсветка ошибок после изменения.

Из Codex

Единый путь: запрос разрешения, безопасный запуск, понятный результат.

Из Hermes

Жесткая граница для секретов: агент не должен видеть токены и ключи напрямую.

Из CodeWhale

Умная работа с огромным выводом: не засорять чат, а давать краткое превью и ссылку.

Из NanoClaw

“Системное действие”: агент просит, а привилегированный хост выполняет только после проверки.

Из Pi-agents

Граф работ: несколько агентов, fork/join, бюджет, понятный результат команды.

Источники и как сделана страница

Для удобства применены базовые правила хороших comparison-доков: фиксированная первая колонка, фильтры, короткие карточки, подсветка отличий и разделение “сводка / детали”.

  • NN/g: Comparison Tables for Products, Services, and Features — почему таблицы сравнения помогают принимать решение.
  • Baymard: Comparison Tool examples — как показывать сравнение товаров и функций без перегруза.
  • Pencil & Paper: Enterprise Data Tables — sticky columns, широкие таблицы, сканирование больших наборов.
  • LogRocket: Feature comparison tables — как выбирать признаки сравнения под аудиторию.
  • Локальные research-отчеты: projects-to-research/tool-analysis/*.md, README Kimi Code и текущий каталог Mothership crates/mothership-core/src/tools/catalog.rs.

Главное для нас

Не надо выигрывать количеством тулов. Нужно, чтобы человек понимал: что агент хочет сделать, зачем, насколько это опасно и как отменить.

Логическая проверка

audio_transcribe — ввод. auto_safe — режим. list_files — не обязательная отдельная тула. В текущем каталоге Mothership это в целом соблюдено.
