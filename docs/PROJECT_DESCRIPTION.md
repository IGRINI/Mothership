# Mothership — описание проекта

Mothership — это приложение для работы с AI-агентом, который живёт на компьютере пользователя и помогает писать код, вести проекты, запускать задачи, читать файлы, работать с терминалом и сохранять историю всей работы.

Главная идея: компьютер пользователя — это “главная станция”, где работает агент. Пользователь может управлять им как с самого компьютера, так и удалённо с телефона.

## Что мы делаем

Мы делаем быстрый, отзывчивый и удобный интерфейс для AI-агента, который помогает разработчику работать над проектами.

Пользователь может:

- создавать и открывать чаты с агентом;
- обсуждать задачи по проекту;
- просить агента читать, менять и объяснять код;
- смотреть историю прошлых диалогов;
- продолжать старые задачи;
- запускать долгие процессы и возвращаться к ним позже;
- управлять агентом с телефона, пока сам компьютер продолжает выполнять работу.

Приложение должно ощущаться не как обычный чат, а как рабочее место для разработки с AI.

## Главный пользовательский сценарий

Пользователь сидит за компьютером, работает над проектом и общается с агентом.

Потом он уходит: в кафе, ресторан, дорогу или просто отходит от рабочего места.

С телефона он открывает приложение, видит те же чаты, ту же историю, текущие задачи и может продолжить работу.

Агент всё ещё работает на компьютере пользователя. Телефон — это только удобный удалённый пульт управления.

## Ключевое ощущение продукта

Приложение должно быть:

- очень быстрым;
- плавным;
- отзывчивым;
- спокойным;
- не перегруженным;
- удобным для долгой работы;
- визуально современным;
- без ощущения тяжёлой тормозящей программы.

Даже если у пользователя много чатов, длинная история и большие ответы, интерфейс не должен зависать. Лучше показать данные постепенно, но сразу реагировать на действия пользователя.

## Что важно

Главный приоритет — отзывчивость.

Если пользователь нажал на чат, ввёл текст, отправил сообщение, переключил вкладку или открыл историю — интерфейс должен реагировать мгновенно.

Не нужно пытаться показать всё сразу. Лучше сначала показать самое важное, а остальное догрузить позже.

Приложение должно создавать ощущение, что оно всегда живое и готово к действию.

## Основные части приложения

### Чаты

Чат — центральная часть приложения.

В чате пользователь общается с AI-агентом, ставит задачи, получает ответы, смотрит ход выполнения и возвращается к старым обсуждениям.

История чатов должна быть удобной, быстрой и понятной.

### История

История — важная часть продукта.

Пользователь должен легко находить старые чаты, продолжать незавершённые задачи и понимать, что происходило раньше.

Даже если истории очень много, приложение не должно становиться медленным.

### Агент

Агент — это рабочий помощник пользователя.

Он может анализировать проект, предлагать изменения, выполнять задачи, помогать с кодом и объяснять свои действия.

Агент работает на компьютере пользователя, а интерфейс только управляет им и показывает результат.

### Авторизация AI-провайдеров

Mothership должен самостоятельно подключать AI-провайдеров. Приложение не должно зависеть от Claude Code, Codex CLI или другого внешнего агентского клиента как от владельца авторизации.

Ближайшая цель — поддержать OAuth-подключение OpenAI через Codex OAuth и подключение Anthropic через paste OAuth-токена. Самостоятельный Anthropic OAuth flow Mothership не запускает: Anthropic не предоставляет публичной регистрации OAuth client'а для third-party приложений, поэтому пользователь сам получает токен (любым доступным способом) и вставляет его в Mothership. Архитектура остаётся расширяемой: позже те же механизмы должны принять API keys, полноценный Anthropic OAuth (когда он станет публично доступен) и других провайдеров без переделки Core.

Пользовательское требование: Core должен быть одинаковым для всех провайдеров и способов входа. OAuth, API key и будущие методы авторизации — это адаптеры вокруг одного общего ProviderAuth Core.

Секреты провайдеров не должны попадать в интерфейс, чат, историю, логи, окружение sidecar или агентские prompts. Агент должен работать через Mothership Core/gateway, а не через сырые токены.

### Удалённый доступ

Удалённый доступ нужен не как трансляция экрана, а как полноценный мобильный клиент.

С телефона пользователь должен видеть свои чаты, писать сообщения, следить за прогрессом и управлять задачами.

Компьютер остаётся главным местом, где выполняется работа.

## Принципы дизайна

Интерфейс должен быть современным, минималистичным и практичным.

Он не должен выглядеть как старое системное приложение. Он должен ощущаться как современный AI-продукт для разработчиков.

Визуальный стиль:

- тёмная тема как основной режим;
- чистая типографика;
- аккуратные отступы;
- понятная структура;
- минимум визуального шума;
- плавные переходы;
- удобная навигация;
- акцент на контенте, а не на украшениях.

## Принципы поведения интерфейса

Интерфейс должен всегда оставаться управляемым.

Если что-то грузится, пользователь всё равно должен иметь возможность печатать, переключаться между чатами, открывать другие разделы и продолжать работу.

Долгие операции не должны блокировать приложение.

Приложение может показывать скелетоны, заглушки, статусы загрузки и постепенное появление данных, но не должно зависать.

## Чего не должно быть

Приложение не должно ощущаться как тяжёлая программа, которая начинает тормозить после большого количества чатов.

Не должно быть ситуации, когда история стала большой — и весь интерфейс стал неотзывчивым.

Не нужно загружать и показывать всё сразу, если пользователь этого не видит.

Не нужно превращать приложение в перегруженную IDE. Это в первую очередь AI-рабочее место, а не полноценная замена редактору кода.

## Цель проекта

Создать приложение, в котором разработчик может комфортно работать с локальным AI-агентом, не теряя доступ к нему даже вне компьютера.

Идеальный результат:

> “Мой агент работает на моём ПК, а я могу управлять им откуда угодно.”

Mothership — это главная станция для AI-разработки.

## Зафиксированные цели ProviderAuth

- Самостоятельная авторизация OpenAI через Codex OAuth.
- Подключение Anthropic через paste OAuth-токена; Mothership не запускает свой OAuth flow для Anthropic и не зависит от Claude Code в runtime. Полноценный Anthropic OAuth — отложенная цель, зависящая от появления публичной client registration.
- Единый ProviderAuth Core для OAuth, OAuth token paste, API keys и будущих провайдеров.
- Расширяемая adapter-модель: провайдеры и способы входа добавляются без изменения chat/run логики.
- Изоляция секретов по модели vault/gateway: сырые токены не попадают в UI и агентский runtime.
- Подробное архитектурное решение хранится в [Provider Auth](PROVIDER_AUTH.md).
